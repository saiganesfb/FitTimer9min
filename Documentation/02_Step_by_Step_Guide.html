1. Prerequisites

You need exactly two things:

🌐 Any modern browser (Chrome, Edge, Firefox)
✎ Any text editor (VS Code, Notepad++, or Notepad)
That's it! No Node.js, no Python, no terminal commands, no npm install. Just files + browser.

2. Create the Folder Structure

Create a folder called FitnessTracker anywhere on your computer. Inside it, create:

FitnessTracker/ app/ ← The actual app lives here index.html ← Open this in browser to use style.css ← All visual styling (dark theme) db.js ← Database layer (IndexedDB) script.js ← All logic (timer, profiles, history) Documentation/ ← Learning docs (you're reading one) 01_Learning_and_Concepts.html 02_Step_by_Step_Guide.html

What each file does:

📄

index.html

The skeleton — defines what elements exist (profile selector, timer, tabs, dialogs). Links to CSS and JS files.

🎨

style.css

The look — dark theme, colors, animations, tab switching, calendar grid, dialog overlays.

💾

db.js

The memory — IndexedDB wrapper. Opens the database, creates tables (users + sessions), provides functions to add/get data.

⚙

script.js

The brain — timer countdown, profile login, stop dialog, calendar rendering, streak calculation, data export.

💡 Why 4 files?
Separation of concerns: each file does ONE job. If you want to change colors → style.css. Fix a bug in the timer → script.js. Change how data is stored → db.js. This makes the code easy to maintain.

5. Create db.js (The Memory)

This is the database layer — a thin wrapper around the browser's built-in IndexedDB.

Why a separate file? IndexedDB has a verbose API (callbacks, events). db.js wraps it into simple async/await functions so the rest of the code stays clean.

What db.js provides:

FunctionPurposeReturns
openDB()Open (or create) the database + tablesDatabase connection
addUser(user)Save a new user profileGenerated ID
getAllUsers()List all profiles (for selector)Array of users
getUser(id)Load one user's profileUser object
updateUser(user)Edit profile (name, weight, goal)—
addSession(session)Record a workoutGenerated ID
getSessionsByUser(userId)All workouts for one personArray of sessions
exportUserData(userId)Bundle user + sessions for backupJSON object

How IndexedDB works (the concept):

// 1. Ask the browser to open a database named 'FitTimerDB'
const request = indexedDB.open('FitTimerDB', 1);

// 2. If it's the FIRST time, create the tables:
request.onupgradeneeded = (event) => {
    const db = event.target.result;
    db.createObjectStore('users', { keyPath: 'id', autoIncrement: true });
    db.createObjectStore('sessions', { keyPath: 'id', autoIncrement: true });
};

// 3. To write data: open a "transaction", get the table, call .add()
// 4. To read data: open a transaction, get the table, call .getAll()
Layman translation: IndexedDB is like a filing cabinet built into your browser. Each "object store" (users, sessions) is a drawer. You put records in, you pull records out. The browser handles the filing — you just call addUser() or getSessionsByUser().

Detailed steps:

Open in Browser

Double-click app/index.html — it opens in your default browser. No server needed.

Create or Pick Profile

First time: Click "New Profile" → enter name, height (optional), weight (optional), daily goal.
Returning: Click your name from the list.

Select Duration & START

Click one of: 9 / 15 / 30 / 45 min. Then hit START (or press Space). The ring starts filling.

Work Out!

The ring fills as time passes. You can pause anytime (Space or Pause button).

Finish or Stop Early

Timer finishes: Celebration popup! Auto-saved.
Need to stop early? Press STOP → pick "Record" (saves partial time), "Discard" (throw away), or "Continue" (resume).

Check History

Click the History tab → see a calendar with green dots on workout days. Navigate months with arrows. See yearly stats.

8. Check Your Data

Your workout data is stored in the browser's IndexedDB (a real database, not just text). To inspect it:

Open DevTools

Press F12 (or right-click page → Inspect)

Navigate to IndexedDB

Chrome/Edge: Application tab → Storage → IndexedDB → FitTimerDB
Firefox: Storage tab → Indexed DB → FitTimerDB

Browse Tables

Click users to see profiles. Click sessions to see all workouts.

TableContainsExample Record
usersUser profiles{id:1, name:"Sai", height:175, weight:72, goal:15}
sessionsWorkout records{id:1, userId:1, date:"2026-05-17T...", duration:15, completed:true}
Easier way: Use the Profile tab → Export Data button in the app itself. It downloads a JSON file with all your data — no DevTools needed!

9. Customization

Change Colors

Edit the :root variables at the top of style.css:

:root {
    --primary: #6c63ff;     /* Change this to your favorite color */
    --accent: #ff6584;      /* Secondary accent */
    --success: #4ecdc4;     /* Timer progress color */
}

Add More Duration Options

In index.html, add a button inside .duration-selector:

<button class="duration-btn" data-minutes="60">60 min</button>

The JavaScript automatically picks up any button with data-minutes.

Change Celebration Messages

In script.js, find the messages array inside the celebration function and edit/add your own motivational quotes.

10. Transfer to Another Computer

Move the App

  1. Copy the entire FitnessTracker/app/ folder (USB, email, cloud)
  2. Open index.html in a browser on the new machine
  3. Done! (Starts fresh — previous data is in the old browser's IndexedDB)

Transfer Workout Data

Easy method (built into the app):

On old computer: Profile tab → click "Export Data" → saves a .json file

On new computer: Open the app, create the same profile, then import the JSON (future feature) or manually paste via DevTools console:
// In Console (F12): paste the exported sessions into IndexedDB
Why data doesn't auto-transfer: IndexedDB lives inside ONE browser on ONE computer. It's like a diary locked in a desk drawer — you can photocopy pages (export), but the diary itself stays put. For cross-device sync, you'd need a cloud service (Firebase, Supabase) — that's a future upgrade.

11. Troubleshooting

ProblemSolution
Timer doesn't startOpen console (F12) — check for red errors. Is db.js loaded before script.js?
Profile selector is emptyFirst time? Click "New Profile". If not first time, check IndexedDB in DevTools.
Data disappearedDid you clear browser data? IndexedDB gets wiped with "Clear all site data".
Calendar shows wrong monthClick the ← → arrows to navigate. It starts on current month.
Looks broken on phoneEnsure <meta name="viewport"> is in HTML head
Progress ring not fillingCheck console for errors in the interval function
Space bar scrolls pageNormal browser behavior — the JS preventDefault() should handle it
"Record" saves 0 minutesYou stopped immediately. Need at least 1 minute elapsed.
