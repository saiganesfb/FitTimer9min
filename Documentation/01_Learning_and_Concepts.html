1. The Problem We're Solving

You want to work out but struggle with consistency. The friction points are:

  • Too much manual tracking — opening apps, logging exercises, sets, reps
  • No fun/reward loop — it feels like a chore
  • Overwhelming time goals — "1 hour at gym" feels impossible some days
💡 The Research Insight:
US research (referenced by Krishashok) shows just 60 min/week of weight training (≈9 min/day) gives maximum health impact. So we're building around 15 min/day or 30 min alternate days.

2. The Solution: Pomodoro-Style Workout Timer

A single-purpose app that:

  1. You set your workout duration (9 / 15 / 30 / 45 min)
  2. Click ONE button to start
  3. Timer runs with visual feedback (progress ring, pulse animation)
  4. When timer completes → session auto-recorded (zero additional input)
  5. Dashboard shows your streak, history, and stats
Key Design Principle:
The fewer clicks between "I should work out" and "I'm working out," the more likely you'll do it. Every screen, every form field, every extra tap is a chance to quit.

Why IndexedDB?

Your workout data is stored in the browser's IndexedDB — a real database built into every browser:

// Open (or create) the database const request = indexedDB.open('FitTimerDB', 1); // Define tables on first run: request.onupgradeneeded = (event) => { const db = event.target.result; db.createObjectStore('users', { keyPath: 'id', autoIncrement: true }); db.createObjectStore('sessions', { keyPath: 'id', autoIncrement: true }); };
Why IndexedDB wins:
• Real database (tables, indexes, queries)
• Multi-user support (userId foreign key)
• Hundreds of MB storage
• Works offline, zero setup
• Structured data (not just strings)
Tradeoffs:
• Data lives in ONE browser
• More complex API than localStorage
• Not synced across devices
• We add export/import for backup

5. Key Code Concepts Explained

The Timer (setInterval)

JavaScript's setInterval calls a function repeatedly at a fixed delay:

let timerInterval = null; let remainingSeconds = 15 * 60; // 15 minutes in seconds function startTimer() { timerInterval = setInterval(() => { remainingSeconds--; updateDisplay(); // Update the UI every second if (remainingSeconds <= 0) { clearInterval(timerInterval); // Stop the timer recordSession(); // AUTO-SAVE the workout! celebrate(); // Fun animation } }, 1000); // Runs every 1000ms = 1 second }
💡 How it works:
• setInterval calls the arrow function every 1000ms (1 second)
• Each call decrements remainingSeconds
• When it hits 0 → stop timer, save session, show celebration
• clearInterval stops the repeating calls

Recording a Session (Auto-Save to IndexedDB)

async function completeSession(isPartial) { const session = { userId: currentUserId, // WHO (from profile login) date: new Date().toISOString(), // WHEN (system clock) duration: isPartial // HOW LONG ? Math.round((totalSeconds - remainingSeconds) / 60) : selectedDuration, targetDuration: selectedDuration, // What they aimed for completed: !isPartial // Full or stopped early }; await addSession(session); // Write to IndexedDB (db.js) celebrate(); // Show celebration! }
Why this is powerful:
Zero user input needed! The app knows: WHO (login), WHEN (system clock), HOW LONG (timer), and whether they finished (timer reached zero or they stopped early). The user just works out.
📚 Analogy: Auto-Checkout at a Library

When you return a book, the machine scans the barcode and records: who (your card), what (the book), when (timestamp). You don't fill out a form.

Same here — your profile = library card, the timer = the book's due date, and IndexedDB = the library computer that logs it all automatically.

The Stop Dialog (New! User choice when stopping early)

function showStopDialog() { pauseTimer(); // Freeze the clock const elapsed = Math.round((totalSeconds - remainingSeconds) / 60); dialogMsg.textContent = `You did ${elapsed} of ${selectedDuration} min`; stopDialog.classList.remove('hidden'); // Show the 3-option popup } // User picks: Record (saves partial) | Discard (reset) | Continue (resume)
💡 Design principle: Never throw away effort. If someone did 8 of 15 minutes and needs to stop, that 8 minutes still counts. The "Record" option saves it with completed: false so history shows what actually happened.

Calculating Streaks

function calculateStreak(sessions) { // Get unique dates, sorted most recent first const uniqueDates = [...new Set( sessions.map(s => new Date(s.date).toDateString()) )].sort((a, b) => new Date(b) - new Date(a)); let streak = 0; let checkDate = new Date(); // Start from today for (const dateStr of uniqueDates) { if (dateStr === checkDate.toDateString()) { streak++; checkDate.setDate(checkDate.getDate() - 1); // Go back 1 day } else { break; } // Streak broken } return streak; }

The Progress Ring (CSS conic-gradient)

// JavaScript calculates the angle: const progress = ((totalSeconds - remainingSeconds) / totalSeconds) * 360; // Then sets it as a CSS conic-gradient: timerRing.style.background = `conic-gradient( #4ecdc4 ${progress}deg, /* Green = done portion */ #2a2a4a ${progress}deg /* Dark = remaining */ )`;
🎨 Think of it like a pie chart:

At 0% → entire circle is grey (no progress)
At 50% → half green, half grey
At 100% → entire circle is green (done!)

conic-gradient draws colors in a circle like slicing a pie.

7. PWA — Use as Android/Phone App

A Progressive Web App (PWA) makes your website behave like a native app on any phone or computer.

📱 Analogy: A Restaurant vs Home Cooking

Native app (Play Store) = eating at a restaurant. Someone else built the kitchen, you just walk in.
PWA = home cooking with a beautiful plating. Same food, YOUR kitchen, no middleman.

The phone can't tell the difference once it's "installed" — it gets a home screen icon, full screen, works offline. But YOU control the code.

What makes it a PWA? (3 additions)

Technical: service-worker.js explained

// 1. INSTALL event: cache all app files self.addEventListener('install', event => { caches.open('fittimer-v2').then(cache => cache.addAll([ './index.html', './style.css', './db.js', './script.js' ])); }); // 2. FETCH event: serve from cache (offline!) or network self.addEventListener('fetch', event => { event.respondWith( caches.match(event.request) // Try cache first .then(cached => cached || fetch(event.request)) // Else network ); });
💡 Key insight: The service worker is like a helpful assistant that sits between your app and the internet. First visit: it downloads and caches everything. Next visit: it serves from cache instantly — even with no WiFi. Your phone thinks it's a native app.
PWA vs Native App:
• No Play Store needed
• No Android Studio
• < 100 KB vs 50-200 MB
• Instant updates (refresh)
• Works on ANY phone/tablet/PC
PWA requirements:
• HTTPS (GitHub Pages = free)
• manifest.json with icons
• Service worker registered
• file:// won't work (needs a server)
